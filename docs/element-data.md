# Periodic table data

## Principle

Data is **vendored**: a script downloads it into `data/elements/` exactly as
published, it's committed, and pages are built from those files. Nothing is
fetched from third parties when the site is built or viewed. The owner asked for
this explicitly: don't "just fetch it from the API".

## Sources

| File | Source | License | Used for |
|---|---|---|---|
| `bowserinator.json` | [Periodic-Table-JSON](https://github.com/Bowserinator/Periodic-Table-JSON) (raw GitHub) | **CC BY-SA 3.0**: attribution required, derived data is share-alike | layout (`xpos`/`ypos`), names, summaries, Wikipedia links, appearance, electron configuration, shells, group/period/block, discovered by, named by |
| `pubchem.json` | [PubChem periodic table](https://pubchem.ncbi.nlm.nih.gov/periodic-table/) REST (`/rest/pug/periodictable/JSON`) | US government work | atomic mass, category (`GroupBlock`), standard state, oxidation states, electronegativity, radius, ionisation energy, electron affinity, melting/boiling point, density, year discovered |
| `corrections.json` | hand-written | n/a | fixes applied on top of PubChem (below) |
| `SOURCES.md` | generated by the script | n/a | where each file came from, and when |

The two are joined by atomic number (they agree on number and symbol for all
118). PubChem is used for categories because its 10 are clean; Bowserinator's
include things like "unknown, probably transition metal".

## Refreshing

```sh
script/pull-elements        # plain Ruby stdlib; no gems
git diff data/elements/     # review what changed upstream
```

- The script checks each download parses and has elements before overwriting.
- It **regenerates `SOURCES.md`**, so edit the template in the script, not the
  file.
- If a correction no longer applies, the page build fails with
  `corrections.json: PubChem <field> for element <n> is now …; review the correction`.
  Delete the correction if upstream fixed it; otherwise update `replaces`.

PubChem answers plain HTTP requests (the script's `Net::HTTP`) fine but has
returned 503 to headless-browser fetches. That's a block on browsers, not on
this machine's IP. Test with the actual client before concluding a source is
unreachable.

## Corrections

`corrections.json` holds fixes where the source is wrong, each with the field,
the new `value`, the value it `replaces`, a `reason` and a `source`. The weave
file applies them when the page is built and refuses to build if `replaces`
doesn't match, so a correction can never silently override changed upstream
data. The page footer names the corrected elements.

Current corrections: PubChem dates **aluminium** and **calcium** as "Ancient"
(their compounds, alum and lime, were ancient). They're corrected to their
isolation years, 1825 and 1808, matching how PubChem dates Na, K and Mg.
Reviewed and deliberately *not* corrected: Zn, Pt, Bi, which Wikipedia calls
pre-modern while PubChem gives their European isolation years. That's
defensible.

## Quirks to know

- **Units** (PubChem): mass u, radius pm (van der Waals), ionisation energy and
  electron affinity eV, melting and boiling points K, density g/cm³. Confirmed
  from values (H: 13.81 K, 120 pm, 13.598 eV).
- **Element 119 (Uue)** is only in Bowserinator (hypothetical) and is left out.
  The table has 118.
- Bowserinator puts f-block elements in "group 3"; the popover shows no group
  for the f-block.
- Bowserinator marks predicted configurations with a leading `*`; shown as
  "(predicted)".
- Some Bowserinator Wikipedia URLs contain spaces; they're turned into `_`.
- Names: PubChem says "Aluminum", Bowserinator "Aluminium". Display uses
  Bowserinator's.
- Bowserinator `discovered_by` is sometimes a date ("5000 BC"), and its summary
  masses can differ from PubChem's mass (Hydrogen 1.00794 vs 1.0080).
- PubChem `StandardState` can be "Expected to be a Gas", which is more honest
  than Bowserinator's `phase` for superheavy elements, so that's what's shown.
- Bowserinator also links images (Wikimedia photos, Bohr models on Google
  storage). They're unused because they'd be fetched from third parties at view
  time. Using them means vendoring the files *and* honouring each image's own
  license (`image.attribution` in the JSON).
